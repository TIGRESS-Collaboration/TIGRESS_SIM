# HPGe Waveform Position Reconstruction

This folder contains the data-export, neural-network training, and real-waveform inference scripts used to reconstruct interaction coordinates in the segmented Gimpy B HPGe detector.

The workflow trains a two-stage one-dimensional convolutional neural network on simulated, single-cluster SolidStateDetectors.jl waveforms and then applies the trained model to real nine-contact detector waveforms.

## Folder contents

### `julia-to-pytorch-data.jl`

Converts the Julia ML dataset into binary arrays that NumPy and PyTorch can load efficiently.

The source Julia dataset is expected to contain:

- corrected SSD waveforms in keV;
- energy-weighted interaction coordinates in SSD coordinates;
- training, validation, and test indices;
- collecting-contact labels;
- deposited energies;
- training-set waveform normalization statistics.

The exporter explicitly converts Julia column-major arrays into NumPy-compatible C-order arrays. This conversion is required to preserve event, contact, time-sample, and coordinate ordering.

### `CNN_train.py`

Trains the final two-stage PyTorch model.

Stage 1 trains the CNN backbone and coordinate regression head using mean squared error. Stage 2 reloads the best Stage 1 checkpoint, freezes the backbone and coordinate head, and trains a separate uncertainty head using Gaussian negative log likelihood.

The final model predicts:

- `x` coordinate in millimetres;
- `y` coordinate in millimetres;
- `z` coordinate in SSD coordinates in millimetres;
- uncertainty `sigma_x`;
- uncertainty `sigma_y`;
- uncertainty `sigma_z`.

### `classify_real_waveforms.py`

Loads the final Stage 2 checkpoint and predicts coordinates and uncertainties for real nine-contact waveforms.

The script:

- parses complete real detector events;
- subtracts the baseline from each channel;
- converts ADC values to keV;
- optionally aligns events using the core constant-fraction crossing;
- applies the training-set channel standardization;
- predicts coordinates and uncertainties;
- writes the predictions to CSV;
- creates an `x-y` hit map colored by predicted uncertainty.

### Julia

The exporter uses Julia's built-in `Serialization` package.

A compatible Julia environment is required to deserialize the dataset generated by the SSD dataset-building script.

### Python

The training and inference scripts require Python 3 and the following packages:

```bash
pip install numpy torch matplotlib
```

If CUDA is available, install the appropriate CUDA-enabled PyTorch build for the system. Otherwise, the scripts run on CPU.

Check the PyTorch device configuration with:

```bash
python -c "import torch; print(torch.__version__); print(torch.cuda.is_available()); print(torch.version.cuda)"
```

### Tensor organization

The waveform tensor is stored as:

```text
[event, contact, time]
```

with shape:

```text
[N, 9, 100]
```

The contact order is:

```text
1, 2, 3, 4, 5, 6, 7, 8, core
```

The coordinate tensor has shape:

```text
[N, 3]
```

with columns:

```text
x_mm, y_mm, z_ssd_mm
```

### Round-trip validation

The exporter prints reference values for the first event. The Python script should load the same values.

For example:

```text
Julia X[1,1,...] = Python X[0,0,...]
Julia X[1,9,...] = Python X[0,8,...]
Julia y[1,:]     = Python y[0,:]
```

Do not train the model if these values do not agree. A disagreement usually indicates an array-order problem.

## 2. Train the CNN

Verify the hard-coded paths near the top of `CNN_train.py`:

```python
data_dir = "/data1/flerner/hpge_sims/CNN/ml_single_cluster_dataset/pytorch_export_v2"
output_dir = "/data1/flerner/hpge_sims/CNN/ml_single_cluster_dataset/cnn_two_stage"
```

Run training:

```bash
python CNN_train.py
```

### Stage 1: coordinate model

Stage 1 trains:

```text
9 x 100 waveform
    -> temporal CNN backbone
    -> coordinate MLP
    -> normalized x, y, z
```

The loss is normalized-coordinate MSE:

```python
loss = torch.mean((prediction - target) ** 2)
```

The checkpoint with the lowest validation coordinate MSE is saved as:

```text
best_stage1_coordinate_model.pt
```

### Stage 2: uncertainty model

Before Stage 2 begins, the script reloads the best Stage 1 checkpoint.

The following components are frozen:

- CNN backbone;
- coordinate head;
- BatchNorm running statistics in the frozen backbone.

Only the uncertainty head is trained. The uncertainty head receives the frozen CNN features and the frozen coordinate prediction and outputs three log variances.

The Stage 2 loss is Gaussian negative log likelihood:

```text
0.5 * [exp(-log_variance) * squared_error + log_variance]
```

The final self-contained checkpoint is:

```text
best_stage2_uncertainty_model.pt
```

This checkpoint contains:

- the best Stage 1 backbone;
- the best Stage 1 coordinate head;
- the trained Stage 2 uncertainty head;
- waveform standardization values;
- coordinate normalization values;
- model configuration;
- validation metrics.

Only the Stage 2 checkpoint is required for final inference because it includes all three model components.

### Adaptive pooling

The final model uses temporal adaptive pooling. The configured number of pooling bins must match during training and inference.

For example:

```python
pool_bins = 20
```

A larger number of bins preserves more coarse timing information, including rise-time and mirror-pulse structure, but increases the size of the MLP input.

### Saved training outputs

The output directory includes:


### Important position metrics

The scripts report:

- coordinate MAE and RMSE;
- mean 3D error;
- median 3D error;
- 68th-percentile 3D error;
- 90th-percentile 3D error.

The 3D error is:

```text
sqrt((pred_x - true_x)^2 +
     (pred_y - true_y)^2 +
     (pred_z - true_z)^2)
```

### Uncertainty metrics

The uncertainty evaluation reports:

- median predicted `sigma_x`, `sigma_y`, and `sigma_z`;
- 1-sigma and 2-sigma coverage;
- standardized residual RMS;
- correlation between predicted uncertainty and actual absolute error;
- correlation between the 3D uncertainty proxy and actual 3D error.

For an ideally calibrated Gaussian coordinate uncertainty:

```text
1-sigma coverage is approximately 68.3%
2-sigma coverage is approximately 95.4%
standardized residual RMS is approximately 1.0
```

The scalar uncertainty used for plots is:

```text
sigma_3d_proxy = sqrt(sigma_x^2 + sigma_y^2 + sigma_z^2)
```

This quantity is a convenient summary. It is not a spherical 68% containment radius.

### Real-waveform preprocessing

The inference script must reproduce the preprocessing convention used for the real superpulse fit and simulated training data.

The current preprocessing includes:

1. reading complete nine-contact events;
2. baseline subtraction;
3. ADC-to-keV conversion;
4. optional core-polarity adjustment;
5. optional event timing alignment;
6. training-set channel standardization;
7. CNN inference.

The stored training mean and standard deviation are applied as:

```text
standardized_waveform =
    (waveform_keV - training_channel_mean) /
    training_channel_std
```

These values are fixed and must not be recalculated from the real events.

### Timing alignment

Event-level alignment is disabled by default:

```python
ALIGN_REAL_EVENTS = False
```

Enable it only if individual real events are not already in the same timing convention as the training waveforms:

```python
ALIGN_REAL_EVENTS = True
```

The alignment reference sample should be determined from the simulated training waveforms rather than selected arbitrarily.


Changing plot limits only hides visually distant predictions. Predictions outside the detector should still be retained and flagged in the CSV for investigation.

## Detector and coordinate conventions

The model predicts coordinates in the SSD detector coordinate system.

Approximate coordinate ranges in the edge-selected training data are:

```text
x: approximately -28 to +28 mm
y: approximately -28 to +28 mm
z: approximately   1 to 89 mm
```

The training dataset includes compact, single-cluster simulated events. The edge-selected version requires the retained hit cluster to be at least 1 mm from the modeled detector boundary.

The edge model includes:

- outer cylindrical boundary;
- octagonal flats;
- top and bottom faces;
- tapered top planes;
- offset rounded core bore.

## Important limitations

### Simulation-to-real transfer

The model is trained using SSD waveforms transformed to resemble measured detector signals. Excellent performance on the simulated test set does not automatically imply identical performance on real data.

### Single-cluster training domain

The coordinate model was trained on simulated events containing one compact spatial cluster. Real multi-site events can be outside the model's training distribution.

### Edge-selected training domain

The model was trained after excluding events close to detector boundaries. Real events do not provide known coordinates before inference, so the same truth-level edge cut cannot be applied directly.

### Unconstrained coordinate output

The coordinate head ends with a linear layer and can mathematically predict any real number. A real waveform that is unlike the training data can produce a coordinate outside the detector.

Do not silently clip predictions to the detector boundary. Clipping can create artificial hit concentrations. Instead:

- retain the original prediction;
- flag nonphysical coordinates;
- inspect the waveform;
- apply geometry-quality and out-of-distribution checks.

### Predicted uncertainty

The uncertainty head estimates residual uncertainty within the simulated training domain. A small predicted uncertainty does not guarantee that a real waveform is in distribution.
