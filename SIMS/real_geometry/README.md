# Gimpy B Tapered and Octagonal Geant4 and SSD Simulation

This folder contains the Geant4 particle-transport simulation and the corresponding `SolidStateDetectors.jl` detector builder.

Unlike the simplified cylindrical model, this detector includes:

- an octagonal mantle;
- two front taper cuts;
- a rounded blind core bore;
- an offset core-bore axis;
- eight segmented outer contacts;
- one core contact;
- constant-thickness outer contacts;
- the Gimpy B impurity gradient.

Geant4 generates gamma-ray energy-deposition positions and energies. The resulting hits are passed to the SSD model generated by `build_gimpy_B_constant_thickness_rounded_core_offset_bore.jl` to calculate electric fields, charge drift, induced signals, and contact-specific waveforms.

# Shared detector geometry

The Geant4 and SSD models should use the same physical crystal dimensions and coordinate conversion.

## Main crystal dimensions

- Material: germanium
- Geant4 material: `G4_Ge`
- SSD material: `HPGe`
- Nominal outer radius: `30 mm`
- Octagonal apothem: `29 mm`
- Crystal height: `90 mm`
- SSD crystal extent: `z = 0 mm` to `90 mm`
- Geant4 crystal extent: `z = -45 mm` to `+45 mm`

The main crystal body is the intersection of:

1. a radius-30 mm cylinder;
2. an axis-aligned square mask;
3. a second square mask rotated by 45 degrees.

Conceptually:

```text
main body = cylinder intersection octagonal mask
```

## Front taper

The front taper starts at:

```text
SSD z = 60 mm
Geant4 z = +15 mm
```

The taper angle is:

```text
22.5 degrees
```

Two subtraction boxes reproduce the two taper planes. The tapered front face is located at:

```text
SSD z = 90 mm
Geant4 z = +45 mm
```

## Rounded blind core bore

The rounded blind core bore consists of:

```text
5-mm-radius cylinder
+
5-mm-radius sphere
```

Shared dimensions:

- bore radius: `5 mm`;
- SSD cylindrical section: `z = 0 mm` to `70 mm`;
- SSD sphere center: `z = 70 mm`;
- SSD bore endpoint: `z = 75 mm`.

In Geant4-centered coordinates:

```text
core-cylinder center z = -10 mm
sphere center z = +25 mm
```

## Offset core-bore axis

The SSD builder deliberately shifts the bore away from `x = 0, y = 0` toward the center of the tapered top face.

The builder uses:

```julia
const CORE_DISTANCE_TO_CONTACT34_FLAT_SIDE = 27.2
const CORE_OFFSET_X = OCT_APOTHEM - CORE_DISTANCE_TO_CONTACT34_FLAT_SIDE
const CORE_OFFSET_Y = 0.0
```

Therefore:

```text
CORE_OFFSET_X = 29.0 - 27.2 = 1.8 mm
CORE_OFFSET_Y = 0.0 mm
```

The Geant4 core bore must use the same offset. A centered Geant4 bore paired with an offset SSD bore produces inconsistent accepted volumes and charge-drift locations.

# Coordinate convention

## Geant4 coordinates

```text
crystal center: z = 0 mm
crystal back:   z = -45 mm
crystal front:  z = +45 mm
```

## SSD coordinates

```text
crystal back:   z = 0 mm
crystal front:  z = 90 mm
```

The hit conversion is:

```text
x_ssd = x_geant4
y_ssd = y_geant4
z_ssd = z_geant4 + 45 mm
```

The Geant4 hit CSV should contain both:

```text
z_g4_mm
z_ssd_mm
```

Later waveform scripts must use `z_ssd_mm` when constructing SSD positions.

# SSD detector builder

## Purpose

`build_gimpy_B_constant_thickness_rounded_core_offset_bore.jl` generates the SSD YAML configuration, loads it as a `Simulation`, calculates the field solutions, and serializes the completed simulation.

## Run switches

```julia
const RUN_ELECTRIC_POTENTIAL = true
const RUN_ELECTRIC_FIELD = true
const RUN_WEIGHTING_POTENTIALS = true
```

For a complete waveform simulation, all three should be enabled.

Weighting-potential calculation is the most time-consuming stage. It can be disabled temporarily while checking YAML syntax or detector geometry.

## Refinement limits

```julia
const REFINEMENT_LIMITS = [1.0, 0.5, 0.25]
```

Examples:

```julia
# Faster geometry and field test
const REFINEMENT_LIMITS = [1.0]

# Higher field resolution
const REFINEMENT_LIMITS = [1.0, 0.5, 0.25, 0.1]
```

Smaller refinement limits improve spatial resolution but increase runtime and memory use.

## Bias and temperature

```julia
const VD = 2500.0
const VOP = 3500.0
const TEMPERATURE = 103.0
```

The outer contacts are held at `0 V`, and the core contact is held at `3500 V`.

`VD` is stored as detector information but the contact potential used in the generated YAML is `VOP`.

## Impurity profile

```julia
const IMP_BOTTOM = 0.95
const IMP_TOP = 2.25
```

These values are in units of:

```text
1e10 cm^-3
```

The profile increases linearly from the back to the front:

```text
SSD z = 0 mm:  0.95e10 cm^-3
SSD z = 90 mm: 2.25e10 cm^-3
```

The builder calculates:

```julia
const IMP_OFFSET_CM3 = IMP_BOTTOM * 1e10
const IMP_GRADIENT_CM4 = (IMP_TOP - IMP_BOTTOM) * 1e10 / 9.0
```

The division by `9.0` corresponds to a 9 cm crystal length.

Geant4 does not use the impurity profile because the impurity concentration has negligible influence on gamma interaction probabilities. SSD uses the profile to calculate the electric potential, field, and carrier drift.

## Constant-thickness outer contacts

```julia
const OUTER_CONTACT_THICKNESS = 0.5
```

The script constructs an inner offset shape using:

```text
inner radius = outer radius - contact thickness
inner octagonal apothem = outer apothem - contact thickness
```

The taper plane is shifted by the approximate normal offset:

```julia
const TAPER_NORMAL_SHIFT = OUTER_CONTACT_THICKNESS / cosd(TAPER_ANGLE)
```

Each outer contact is the intersection of:

```text
segment selector
intersection
(outer crystal shape - inner offset shape)
```

This produces an approximately constant 0.5 mm contact thickness on the cylindrical, octagonal, and tapered surfaces.

## Contact segmentation

Front contacts occupy `z = 70 mm` to `90 mm`:

```text
Front_Q1 -> contact 1 -> phi  90 to 180 degrees
Front_Q2 -> contact 2 -> phi 180 to 270 degrees
Front_Q3 -> contact 3 -> phi 270 to 360 degrees
Front_Q4 -> contact 4 -> phi   0 to  90 degrees
```

Back contacts occupy `z = 0 mm` to `70 mm`:

```text
Back_Q1 -> contact 5 -> phi  90 to 180 degrees
Back_Q2 -> contact 6 -> phi 180 to 270 degrees
Back_Q3 -> contact 7 -> phi 270 to 360 degrees
Back_Q4 -> contact 8 -> phi   0 to  90 degrees
```

The rounded offset bore is contact 9:

```text
Core -> contact 9 -> potential VOP
```

## SSD computational grid

The YAML grid is:

```text
x: -35 mm to +35 mm
y: -35 mm to +35 mm
z:  -5 mm to +95 mm
```

The grid extends beyond the crystal to include surrounding vacuum and all detector boundaries.

## Generated YAML

The builder writes:

```text
gimpy_B_constant_thickness_rounded_core_offset_bore.yaml
```

The generated YAML contains:

- units;
- Cartesian grid;
- vacuum medium;
- HPGe semiconductor;
- temperature;
- linear impurity density;
- complete constructive-solid geometry;
- all nine contacts and potentials.

The script prints the first 120 YAML lines as a quick syntax and geometry check.

## Field calculations

The script performs:

```julia
calculate_electric_potential!(
    sim,
    refinement_limits = REFINEMENT_LIMITS
)
```

followed by:

```julia
calculate_electric_field!(sim)
```

Then it calculates every weighting potential:

```julia
const CONTACTS_FOR_WEIGHTING = 1:9
```

```julia
calculate_weighting_potential!(
    sim,
    contact_id,
    refinement_limits = REFINEMENT_LIMITS
)
```

All weighting potentials are required for nine-contact waveform simulation.

## Serialized SSD output

The completed simulation is written to:

```text
gimpy_B_constant_thickness_rounded_core_offset_bore_sim.jls
```

This file contains the geometry, detector properties, electric field, and weighting potentials.

Later scripts load it using:

```julia
using Serialization
sim = deserialize(
    "gimpy_B_constant_thickness_rounded_core_offset_bore_sim.jls"
)
```

# Geant4 detector simulation

## Active germanium volume

The final active logical volume is normally named:

```text
GimpyBActiveCrystal
```

The exact same name must appear in:

```text
src/DetectorConstruction.cc
src/SteppingAction.cc
```

Example construction:

```cpp
auto* logicCrystal = new G4LogicalVolume(
    solidCrystal,
    germanium,
    "GimpyBActiveCrystal"
);
```

Example stepping check:

```cpp
if (volume->GetName() != "GimpyBActiveCrystal")
{
    return;
}
```

A mismatch transports particles correctly but writes no active-germanium hits.

## Source configuration

The source is defined in:

```text
src/PrimaryGeneratorAction.cc
```

### Gamma energy

```cpp
const G4double CO60_E1 = 1173.2 * keV;
const G4double CO60_E2 = 1332.5 * keV;
```

For isolated 1332.5 keV superpulse production:

```cpp
const bool EMIT_BOTH_CO60_GAMMAS = false;
```

Setting this flag to `true` emits both gamma lines in every event.
### Centered source

Recommended detector-wide source:

```cpp
const G4double SOURCE_X = 0.0 * mm;
const G4double SOURCE_Y = 0.0 * mm;
const G4double SOURCE_Z = 145.0 * mm;
```

The source is 100 mm in front of the Geant4 front face at `z = +45 mm`.

### Cone direction

Recommended centered-source cone:

```cpp
const G4double CONE_HALF_ANGLE = 20.0 * deg;
```

The axial direction must point toward global negative z:

```cpp
G4double uz = -cosTheta;
```

## Physics list

Recommended compact-output configuration:

```cpp
new FTFP_BERT()
```

Do not manually enable fluorescence, Auger production, or PIXE unless the resulting microscopic step volume is specifically required. Explicit activation produced extremely large hit files in testing.

# Geant4 outputs

Outputs are written in the directory from which the executable is run, normally `geant/build`.

## `geant_hits.csv`

```text
event_id,track_id,x_mm,y_mm,z_g4_mm,z_ssd_mm,edep_keV
```

Each row is one positive energy-deposition step in the active germanium.

The preferred hit location is the step midpoint:

```cpp
G4ThreeVector hitPos = 0.5 * (pre + post);
```

A pre-step point may lie exactly on a geometry boundary and later be interpreted by SSD as outside the semiconductor.

## `geant_total_edep.csv`

```text
event_id,total_edep_keV
```

Use the total-energy file for exact full-energy event selection.

## `geant_gamma_tracks.csv`

Contains track and step geometry diagnostics. This file is not required for SSD waveform production and can become large.

---

# Selecting 1332.5 keV events

A generated 1332.5 keV gamma may deposit no energy, partial Compton energy, or its complete energy.

Select full-energy events using the event sum, not a single hit.


The exact method is:

1. select event IDs using `geant_total_edep.csv`;
2. retain every hit row for each accepted event from `geant_hits.csv`.

Apply the full-event energy gate before removing small individual deposits.

# Passing Geant4 hits to SSD

The SSD waveform script should load:

```text
gimpy_B_constant_thickness_rounded_core_offset_bore_sim.jls
```

and use:

```text
x_mm
y_mm
z_ssd_mm
edep_keV
```

Convert millimetres to metres exactly once:

```julia
CartesianPoint{Float32}(
    Float32(x_mm * 1e-3),
    Float32(y_mm * 1e-3),
    Float32(z_ssd_mm * 1e-3)
)
```

If the serialized simulation uses `Float32`, all SSD event positions and relevant simulation parameters must also use `Float32`.
